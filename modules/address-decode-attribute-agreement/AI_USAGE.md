# Address-map integration review

Load [SKILL.md](SKILL.md) through the clone or
[project-local installer](../../INSTALL.md) in your existing AI environment.

> Review these resolved hardware/software views after the integration change.
> Establish initiator and translation scope, reconcile effective permission and
> memory attributes, and inspect intended aliases and required decode ranges.
> Retain native findings and a cited conclusion with the smallest missing evidence.

Provide original exports, generated/consumed revisions, initiator identity,
address units/stage, explicit window correspondence and alias/requirement policy.
Use existing native access evidence when interval agreement does not answer the
actual route or protection question.

A familiar region name, a current header or a passing paired-map report does not
establish that the original binary used those values. Inspect native producer and
software-export ancestry. Keep a favorable report if source review exposes a
wrong normalization or omitted consumer, and append the sourced correction.

The AI can use a native/company method beyond the flat-map profile. Distinguish
its scope and evidence from this helper's result. No model SDK, hosted service or
DVIT installation is required. Optional [context sources](../../CONTEXT_PORT.md)
can supply scoped route relationships and alias rationale; source absence never
triggers installation or a different provider.
