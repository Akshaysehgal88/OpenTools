# Evidence and review boundary

`opentools.physical-context.v1` declares run/design/configuration/phase identity,
selected net and timing endpoint, consumed setup and relationship sources.
`opentools.physical-execution.v1` retains the original tool hash, command, source
hashes, artifact hashes and native exit. Byte identity does not authenticate
consumption, source authority, freshness or approval.

The reader checks exact batch loader/exporter bytes, canonical setup, original
native artifact bytes and completion. It verifies actual floorplan, placements,
blockages, clock and case values against the consumed setup. Source/script/native
changes reject capture. Missing native files are invalid/incomplete intake, not a
hardware failure. Saved source scripts and commands are never executed by review.

Native JSON lines retain instance boxes, pin locations/connectivity, boundary
ports, hard/soft blockages, selected net terminals/bounds, clock/cases, selected
path endpoints/slack and the original placement-check return/message. Coordinates
are native database units. Unknown pin positions remain unknown. Path slack uses
the native ns UI for the pinned tool; the batch loader has no interconnect RC model.

`opentools.physical-policy.v1` binds both original runs and their setup, source,
database, export, SDC, command and tool identities. Independent intent supplies
the selected net/endpoints, one allowed moved instance, clear region in database
coordinates, required hard-blockage protection, rationale, owner and claim strength.
The example factory shows full records. A policy is a supplied review declaration,
not an approval signature. Inspect its original source using the AI workflow.

The helper compares source, library, tool, floorplan, clock/phase, pin connectivity,
selected endpoints and placements outside the intervention. Changed conditions
leave a reported geometric difference unqualified. It separately checks original
region protection, positive-area instance intrusion and native placement results.
Touching region edges is permitted by this selected rule.

The derived metric is the selected native net-terminal bounding-box half perimeter.
It qualifies only known instance-terminal positions with no boundary terminals.
It is not routed wirelength, congestion, extraction or a physical optimization
score. A favorable metric can coexist with an intent violation. Required routing,
timing, throughput, macro-access, power/isolation or complete signoff claims stay
open even if the bounded review matches.

Batch qualification covers one translated instance and one region under the
bundled flat scalar loader, hard-blockage setup, declared binary cases and pinned
OpenROAD version. The generic exporter also supports inspection after a native
saved-database reopen. Other loaders, hierarchical mappings, transformed cells,
boundary-terminal geometry and production checks need their own qualification.
The AI workflow can use existing team tools for those tasks without expanding
this adapter's claims.
