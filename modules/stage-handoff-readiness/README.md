# Execution-stage handoff readiness

Review a control transfer against the receiving stage's image, entry, stack and
readiness requirements. Use the [AI workflow](SKILL.md) and [review record](REVIEW.md)
in the existing integration/handoff process. ROM-to-loader and loader-to-firmware
are examples of the same activity. Your existing AI host is sufficient.

Python 3.10+ standard library, from this directory:

```sh
python examples/create_example.py /tmp/handoff-example --case rom-early
python handoff_review.py /tmp/handoff-example/inventory.json /tmp/handoff-example/journal.json /tmp/handoff-example/policy.json
python -m unittest discover -s tests -v
```

Expected review exit: 1. `rom-ready` and `firmware-valid` are controls.
The helper checks typed image/setup facts, explicit handoff snapshots, observed
first stack accesses and results against independent successor requirements.
Missing facts stay unknown; later readiness cannot replace the handoff snapshot.
Examples are reference fixtures unless generated by the [native recipe](examples/NATIVE.md).

`image_capture.py image.elf` optionally captures actual identity and load metadata
for static identity-mapped x86-64 ELF64 little-endian executables. Other artifact
formats need their native metadata tools. [FORMAT.md](FORMAT.md) describes the
reviewed records; hashes establish identity, not secure-boot authenticity.

Exits: 0 within the supplied observed contract, 1 known finding, 2 incomplete
without a known finding, 3 invalid input/I/O. Findings retain concurrent gaps.
`--output` requires a new file. A helper success does not approve a handoff or
qualify silicon readiness, ECC, cache/MMU behavior or an undocumented ROM sequence.

Install this module with the repository's [project-local installer](../../INSTALL.md).
Optional [context sources](../../CONTEXT_PORT.md) may add scoped requirements or
artifact relationships. No AI SDK or DVIT installation is required.
