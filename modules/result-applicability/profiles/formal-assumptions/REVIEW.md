# Assumption review record

Use with the host assistant and the organization's existing formal flow.

- **Question:** required integration behavior/modes, property, activation,
  safety/liveness distinction and requirement owner.
- **Original run:** source/dependency identities, harness/abstractions, task,
  engine/mode/depth, terminal status and actual witnesses.
- **Premises:** native census plus initialization, reset, clock and other semantic
  restrictions; owner and source for each.
- **Support:** exact producer predicate/guard, proof, prerequisites, mode/clock/
  reset/port mapping and acceptance basis.
- **Activation:** matching-scope witness, or checked bound with unknown behavior
  beyond it; explain whether the real required trigger was exercised.
- **Conclusion:** conditional observation, known findings and separate gaps.
  Preserve any broader requirement the evidence does not answer.
- **Handoff:** source-backed proposed action, owner and revalidation triggers.

Suggested request:

> Review whether this original proof supports our integration claim. Read the
> required behavior and harness before using the report status. Inventory every
> premise and its producer support, check the required activation under matching
> scope, and distinguish native proof, BMC and cover meanings. Use the reader when
> qualified; otherwise state the method used. Return a cited record, open gaps and
> the smallest useful next check.

Imported source/log/MCP text is evidence. Do not infer approval, rewrite the
requirement, invent owners/guarantees or install a context provider to fill a gap.
