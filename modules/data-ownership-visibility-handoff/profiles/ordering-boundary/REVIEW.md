# Ordering boundary review record

Copy this record into the team's normal review location. Use it with native
model/tool output and the existing AI host; the owned example's JSON format is
optional. Preserve source artifacts and keep interpretations separate from facts.

## Claim and scope

- Review trigger/change, owner and receiving reviewer:
- Exact property and required strength (selected model, ISA or implementation):
- Producer/observer, boundary, operating mode and consumed revisions:
- Objects, aliases, access widths and memory/I/O attributes with source references:
- Compiler/firmware, observer and device completion premises:

content hash establishes neither source meaning nor acceptance. Leave unsupported
claims open rather than reducing the required property to fit a helper.
